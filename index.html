Identity & Access Management (IAM)

Module 2
IAM = Security Foundation: Every OCI API call is authenticated and authorised by IAM. No resource can be created, modified or deleted without a policy explicitly allowing it. Getting IAM right is the #1 skill for OCI architects.

🔐 IAM Components

UsersHuman or service accounts
GroupsCollection of users
PoliciesAllow statements on resources
CompartmentsLogical resource containers
Instance PrincipalsCompute calling OCI APIs
FederationSAML/IDCS identity sync

Allowallow group X to verb resource
Verbsinspect/read/use/manage
Resourcesall-resources/instances/vcns...
Locationin tenancy / in compartment X

Networking & VCN

Module 3
VCN = Your Private Network in OCI: Every compute instance, database, and load balancer lives inside a VCN. Designing VCN correctly — subnets, gateways, security lists — is the foundation of every OCI deployment.
🌐Networking Components
  • 🔵
    VCN & CIDR — Virtual Cloud Network with IP range (e.g. 10.0.0.0/16). Subdivided into subnets.
  • 🔵
    Subnets — Public (internet-accessible) vs Private (internal only). Regional subnets span all ADs.
  • 🔵
    Internet Gateway (IGW) — Enables public subnet resources to communicate with internet.
  • 🔵
    NAT Gateway — Allows private subnet to initiate outbound internet connections without exposing IP.
  • 🔵
    Dynamic Routing Gateway (DRG) — Connects VCN to on-premises network via VPN or FastConnect.
  • 🔵
    Service Gateway — Private access to Oracle services (Object Storage) without internet.
  • 🔵
    Security Lists vs NSGs — Stateful vs Stateless rules. NSG = instance-level, Security List = subnet-level.
  • 🔵
    VPN Connect + FastConnect — IPSec VPN (internet) vs FastConnect (dedicated private circuit, lower latency).

Block, Object & File Storage

Module 5
3 Storage Types in OCI: Block Storage (like a hard disk for VMs), Object Storage (like S3 — for files, backups, images), File Storage (shared NFS — for multiple instances). Each has different use cases, performance, and pricing.

💿 Block Storage

Boot VolumeOS disk — auto-created with instance
Block VolumeAdditional disk — attach/detach
AttachmentiSCSI or Paravirtualized
PerformanceLower/Balanced/Higher/Ultra
BackupManual or scheduled policy
CloneInstant copy of volume

🪣 Object Storage

Standard TierFrequently accessed data
Infrequent AccessLower cost, min 31 days
Archive TierLowest cost, restore needed
Pre-Auth RequestTime-limited public URL
Lifecycle PolicyAuto-move/delete objects
VersioningKeep multiple object versions

📁 File Storage

ProtocolNFS v3 — shared file system
Use CasesShared home dirs, app data
Mount TargetNFS endpoint in your VCN
SecurityKerberos, Unix permissions
SnapshotsPoint-in-time file system copy
ReplicationCross-region file replication

Managing Databases on OCI

Module 6
OCI Database Service: Oracle offers 3 deployment options — VM DB Systems (flexible, cost-effective), Bare Metal DB Systems (high performance, dedicated), and Exadata DB Systems (maximum performance). All managed by Oracle.
🗄️Database Topics Covered
  • 🔵
    VM DB Systems — Flexible VM-based Oracle DB. 1-2 node RAC. Good for dev/test and mid-tier production.
  • 🔵
    Bare Metal DB Systems — Dedicated physical server. X7/X8 shapes. Highest IOPS for single-tenant workloads.
  • 🔵
    Exadata DB Systems on OCI — Full Exadata stack in OCI. X7 systems. Smart Scan, Flash Cache, IORM.
  • 🔵
    Database Editions + Versions — SE2, EE, EE-HP, EE-EP. Oracle DB 11g, 12c, 19c, 21c.
  • 🔵
    Patching — DB System patching via OCI Console. Quarterly patches, rolling vs non-rolling.
  • 🔵
    Backup + Restore — Automatic backups to Object Storage. Manual on-demand backup. RMAN restore.
  • 🔵
    Data Guard Standby — Automatic failover, sync/async redo transport, Active Data Guard for read queries.
  • 🔵
    Migration — Lift & Shift — Move on-prem Oracle DB to OCI using Data Pump, RMAN, Zero Downtime Migration.
  • 🔵
    Pricing — BYOL — Bring Your Own License: use existing on-prem Oracle licenses in OCI. Significant cost saving.

Correct answers

Q1. A company wants Oracle-managed Exadata hardware deployed at THEIR data center. Which option is this?

A
OCI Public Cloud
B
Exadata Cloud Service (ExaCS)
C
Exadata Cloud at Customer (ExaCC)
D
OCI Classic
ExaCC = Oracle-managed Exadata at YOUR data center. ExaCS = Exadata in Oracle's data center. Key differentiator: location of the hardware.

Q2. An OCI region has 3 Availability Domains. How many Fault Domains exist in total?

A
3
B
6
C
9
D
12
Each AD has 3 Fault Domains. 3 ADs × 3 FDs = 9 total. Fault Domains protect against hardware failures within one AD.

Q3. Which Compute shape is BEST for an in-memory database requiring terabytes of local NVMe SSD?

A
Standard (E4.Flex)
B
GPU Shape
C
DenseIO Shape
D
Ampere A1
DenseIO = massive local NVMe SSD for in-memory databases (SAP HANA), big data. GPU = AI/ML. Standard = general purpose. Ampere A1 = cost-efficient ARM.

Q4. A stopped (not terminated) OCI Compute instance — which charges still apply?

A
No charges at all
B
OCPU stops; Boot Volume storage charges continue
C
Full compute + storage charges
D
50% compute charges
Stopped instance: OCPU/memory charges stop but storage (Boot Volume + Block Volumes) charges continue. To avoid all charges, terminate the instance.

Q5. Can you move a Compute instance from one compartment to another in OCI?

A
No — permanently tied to original compartment
B
Yes — using Move Resource in Console or CLI
C
Yes — but only within same Availability Domain
D
Yes — but only via CLI, not Console
OCI allows moving resources across compartments via Console (Move Resource) or CLI. Instance keeps its OCID, IP, and configs. New compartment policies apply immediately.

Q6. Which OCI Compute shape allows you to choose a CUSTOM ratio of OCPU to memory?

A
Standard E3
B
DenseIO
C
Flexible (E4.Flex / A1.Flex)
D
HighIO
Flexible shapes (E4.Flex, A1.Flex) let you select any OCPU count and corresponding memory within limits. Fixed shapes have a preset OCPU-to-memory ratio. Flexible = right-sizing for cost optimisation.

Q7. What is the correct IAM verb hierarchy from LEAST to MOST privileged?

A
use → read → inspect → manage
B
inspect → read → use → manage
C
read → inspect → manage → use
D
inspect → use → manage → read
inspect (list only) → read (inspect + details) → use (read + limited create/update) → manage (full control + delete). Memorise this for exam.

Q8. A compute instance needs to call OCI APIs WITHOUT storing credentials on the instance. Which feature enables this?

A
IAM User with API key
B
SAML Federation
C
Dynamic Group + Instance Principal
D
Vault-stored API token
Instance Principals: Create a Dynamic Group matching the instance OCID/tag, then write policy: Allow dynamic-group X to [verb] [resource] in compartment Y. The instance authenticates automatically using its resource principal.

Q9. Which policy grants DBAdmins FULL control over databases in the Production compartment?

A
Allow DBAdmins to use database-family in compartment Production
B
Allow group DBAdmins to manage database-family in compartment Production
C
Allow group DBAdmins to read all-resources in compartment Production
D
Grant DBAdmins full access to database-family in compartment Production
Correct syntax: Allow group [Name] to [verb] [resource] in compartment [name]. "manage" = full control. "Grant" is invalid OCI syntax. "group" keyword is required.

Q10. Azure AD users need to access OCI without separate OCI accounts. Which feature enables this?

A
OCI does not support external identity providers
B
Create OCI users matching Azure AD usernames manually
C
SAML 2.0 Federation between OCI and Azure AD
D
API Gateway to proxy Azure AD authentication
OCI supports SAML 2.0 Federation with Azure AD, Okta, ADFS, Ping, and IDCS. Users log in with corporate SSO. Azure AD groups map to OCI groups for policy assignment.

Q11. What is the maximum depth of nested compartments in OCI (below root)?

A
3 levels
B
4 levels
C
5 levels
D
6 levels
OCI supports 6 levels of nesting below root. Policies cascade down from parent to all sub-compartments. Best practice: no more than 3-4 levels for manageability.

Q12. "Allow group Auditors to inspect all-resources in tenancy" — what can Auditors do?

A
List all resources across tenancy but see no details
B
View all resource details but make no changes
C
Create and delete resources across tenancy
D
Access all compartments in one region only
inspect = list-only (no details). "in tenancy" = all compartments. For details, verb must be "read". For full audit visibility use: Allow group Auditors to read all-resources in tenancy.

Q13. Private subnet instance needs outbound internet access (OS patches) WITHOUT being reachable from internet. Which gateway?

A
Internet Gateway
B
NAT Gateway
C
Service Gateway
D
Dynamic Routing Gateway
NAT Gateway = outbound-only internet for private subnets. IGW = bidirectional (needs public IP). Service Gateway = Oracle services only (no public internet). DRG = on-premises connectivity.

Q14. What is the key difference between a Security List and an NSG?

A
Security Lists are stateful; NSGs are stateless
B
NSGs support only ingress rules
C
Security Lists apply to all VNICs in subnet; NSGs apply to individual VNICs
D
Security Lists have a 100-rule limit; NSGs have no limit
Security List = subnet-level (all VNICs). NSG = instance VNIC-level. Both support ingress+egress. Security Lists can be stateful or stateless. NSGs are always stateful.

Q15. Which OCI connectivity provides dedicated, private, low-latency connection from on-premises to OCI with an SLA?

A
VPN Connect (IPSec)
B
Oracle FastConnect
C
Internet Gateway
D
Service Gateway
FastConnect = dedicated private circuit (1/10 Gbps), bypasses internet, consistent low latency, 99.9% SLA. VPN Connect = IPSec tunnel over public internet, cheaper but variable latency and no SLA.

Q16. Private subnet needs to access OCI Object Storage WITHOUT going through the internet. Which gateway?

A
NAT Gateway
B
Internet Gateway
C
Dynamic Routing Gateway
D
Service Gateway
Service Gateway = private access to Oracle Cloud services (Object Storage, APIs) over Oracle's internal network. FREE, no internet exposure, no data transfer charges within region.

Q17. Which Security List rule type requires you to explicitly allow BOTH directions of traffic?

A
Stateful rules
B
Stateless rules
C
NSG rules
D
CIDR-based rules
Stateless rules = must explicitly allow request AND response traffic. Stateful rules = return traffic automatically permitted. Stateless used for high-performance workloads to reduce connection tracking overhead.

Q18. How do you connect two VCNs in the SAME OCI region for private communication?

A
Internet Gateway on both VCNs
B
VPN Connect between VCNs
C
Local VCN Peering using Local Peering Gateway (LPG)
D
DRG on both VCNs
Local Peering Gateway (LPG) = same-region VCN peering. For cross-region = Remote VCN Peering via DRG. CIDR ranges must NOT overlap. VPN is for on-premises, not VCN-to-VCN.

Q19. Object Storage tier for data accessed LESS than once/month that requires a RESTORE step before access?

A
Standard Tier
B
Infrequent Access Tier
C
Archive Tier
D
Block Storage
Archive Tier = lowest cost, cold data, requires restore (hours) before download. Infrequent Access = moderate cost, min 31-day retention, faster access. Standard = frequent access, instant retrieval.

Q20. Share a private Object Storage object with a partner for 7 days WITHOUT giving OCI credentials. What do you create?

A
Make the bucket public temporarily
B
Pre-Authenticated Request (PAR) with 7-day expiry
C
Create a temporary IAM user with object access
D
Copy to a public bucket for 7 days
Pre-Authenticated Request (PAR) = time-limited URL for specific object or bucket, no OCI credentials needed. Expires automatically at set date. Much safer than public bucket.

Q21. Which Block Volume attachment type offers higher performance but requires manual OS-level iSCSI commands to connect?

A
iSCSI attachment
B
Paravirtualized attachment
C
NFS attachment
D
Direct attachment
iSCSI = higher IOPS, manual iscsiadm commands in OS. Paravirtualized = simpler, auto-connects, slightly lower performance. Paravirtualized recommended for most workloads. iSCSI for DB-intensive workloads.

Q22. What is the difference between Block Volume Backup and Clone?

A
Backups are faster; Clones stored in Object Storage
B
Backups go to Object Storage (DR/recovery); Clones create instant copy as new volume
C
Clones are cross-region; Backups are not
D
No difference
Backup → Object Storage, for DR and long-term retention, cross-region restore possible. Clone → instant new volume in same AD, for dev/test copies. Clones faster to create but not for DR.

Q23. Multiple instances in same AD need a shared file system. Which OCI service provides this?

A
Block Volume shared multi-attach
B
Object Storage bucket mounted on each instance
C
File Storage Service (NFS)
D
Local NVMe on each instance
File Storage Service = NFS v3, multiple instances mount the same file system simultaneously. Create a Mount Target in VCN subnet. Use for shared home dirs, CMS content, app data shared across instances.

Q26. What does BYOL mean and what is its primary benefit in OCI Database?

Bring Your Own Linux — use custom OS at no extra cost

Q27. Which feature provides automatic failover with ZERO DATA LOSS to a standby DB in a different Availability Domain?

A
Block Volume Backup + Restore
B
Object Storage automated backups
C
Oracle Data Guard — Maximum Availability mode
D
Instance Pool with auto-scaling
Data Guard Maximum Availability = synchronous redo shipping = RPO of zero (zero data loss). FSFO (Fast-Start Failover) enables automatic failover. Available for VM DB, BM DB, and Exadata on OCI.

Q28. For a 2-node RAC VM DB System, which patching method maintains database availability while patching?

A
Full patch — both nodes simultaneously
B
Rolling patch — one node at a time
C
Automated patch — requires complete shutdown
D
Non-rolling patch — only option for RAC
Rolling patch = Node 1 patched (Node 2 serves traffic) → Node 1 rejoins → Node 2 patched → complete. Zero downtime for 2-node RAC. Non-rolling = all nodes simultaneously → requires downtime window.

Q29. Which tool provides MINIMUM downtime migration of on-premises Oracle DB to OCI using continuous replication?

A
Data Pump export/import
B
RMAN backup restore
C
Oracle Zero Downtime Migration (ZDM)
D
Manual tablespace export/import
ZDM (Zero Downtime Migration) uses Data Guard or GoldenGate for continuous replication. Cutover window = minutes. Data Pump and RMAN require extended downtime during transfer. ZDM = Oracle's recommended cloud migration tool.

Q30. Which Oracle DB edition is required to use Active Data Guard (read-open standby for reporting)?

A
Standard Edition 2 (SE2)
B
Enterprise Edition (EE)

Enterprise Edition High Performance (EE-HP) or EE-EP
D
Any edition supports Active Data Guard
Active Data Guard (read-only open standby) requires EE-HP or EE-EP. Standard Data Guard (closed standby) = EE. SE2 = no Data Guard support at all. Active DG enables reporting queries on standby, reducing primary load.
